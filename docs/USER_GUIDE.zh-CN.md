## 运行条件与桌面窗口

- Windows 10 / 11，64 位。完整打包版不需要安装 Python 或 Node.js。
- 独立桌面窗口需要 Microsoft Edge WebView2 Runtime。若缺少或无法启动，会提示并使用兼容服务管理器，通过系统浏览器打开工作台。只从 Microsoft 官方渠道安装 WebView2。
- 浏览器辅助采价另需已安装的官方 Microsoft Edge 或 Google Chrome。程序内置其驱动，不自动下载一个完整浏览器。
- 本地图片模型使用 CPU。图片较多或首次重建索引时，界面会显示准备进度，速度取决于主机硬件。
- 基础商品库和本地查重可离线工作。AI、真实商品页面和公共参考汇率各自需要对应的网络访问。

双击桌面「电商产品管理系统」即可打开独立窗口。若本机端口已有同一软件的共享服务，桌面窗口连接该服务，不停止或接管它。关闭自己启动的服务会影响局域网成员与自动备份；请留意关闭提示。

兼容服务管理器可通过 `Midoo.exe --service-manager` 打开。它显示共享地址并提供浏览器访问入口。默认端口为 `8765`，本机地址为 `http://127.0.0.1:8765`。

## 安装升级和卸载

### 首次安装

1. 从项目 [Releases](https://github.com/myflww/ecommerce-product-management-system/releases) 下载 `EcommerceProductManager-Setup-1.7.0.exe`。
2. 双击 Setup，在标准安装窗口确认安装。无需 PowerShell 执行策略调整。
3. 默认按当前用户安装到 `%LOCALAPPDATA%\Programs\EcommerceProductManager`，无需管理员权限。
4. 使用新建的桌面或开始菜单「电商产品管理系统」快捷方式。

安装包不包含发布者的公司商品库、账号或 API 密钥。首次独立运行时创建的是你自己的空库，不会扫描私人目录。也可下载 `EcommerceProductManager-1.7.0-Windows.zip`，完整解压后直接运行 `Midoo.exe`，以便携方式使用；不要直接在压缩包预览内运行。ZIP 中的 `Install-Desktop.cmd` 与 `tools/Install-Desktop.ps1` 是允许执行脚本环境下的备用安装方式。

### 使用已有资料目录

已有库不要重新导入或放入空白替代目录。先备份，再明确指定原库位置，例如：

```powershell
.\EcommerceProductManager-Setup-1.7.0.exe --install --data-dir "D:\Midoo\data"
```

安装产生的 `desktop-config.json` 只供本机选择资料目录，不上传 GitHub。启动参数 `Midoo.exe --data-dir "D:\Midoo\data"` 可覆盖该本机配置，环境变量 `MIDOO_DATA_DIR` 优先级最高。最终以软件「设置与备份 → 局域网与备份」中显示的资料位置为准。

### 升级

1. 在旧版中生成完整备份，另存一份到其他设备。
2. 正常关闭需要替换的旧版程序及其自有共享服务。仅关浏览器页面不一定会停止服务；关闭一个连接既有服务的桌面窗口也不会停止其他进程启动的服务。
3. 运行新版 Setup 更新应用文件，保留原 `data` 和本机资料目录配置；便携用户解压新版并明确保留原库。
4. 启动新版，核对版本、商品数量、图片、SKU 与原价格 / 当前价。首次索引准备完成前，不把“查不到”视为没有重复。

不要在程序运行时手工覆盖数据库。不要将发布包内的新目录与自己保存资料的目录混淆。遇到仍在运行或文件被占用的提示，先正常关闭对应服务，不强行覆盖。

### 卸载

正常关闭已安装程序后，从开始菜单的 Ecommerce Product Manager 文件夹选择 Uninstall，或双击安装目录中的 `Uninstall.exe`，在原生卸载窗口确认。它移除当前用户的应用与匹配快捷方式，保留商品资料。外部指定的数据目录也不会被当作安装文件删除。卸载前仍建议导出备份，并记录实际资料路径。

命令行可使用 `Uninstall.exe --uninstall`；`Uninstall-Desktop.cmd` / `tools/Uninstall-Desktop.ps1` 仅保留为允许脚本环境下的备用入口。没有匹配安装标记时，卸载器不会自行扫描或删除其他程序。

如果确实要销毁商品库或专用浏览器登录资料，请先确认已有必要备份，再单独处理这些资料。删除应用与永久删除公司资料是两件不同的事。

## 首次登录与团队账号

首次打开空库时创建自己的账号和至少 8 位密码，该账号成为工作区唯一「老板」，没有默认账户。升级旧库时，最早创建的旧账号成为老板；时间相同时按内部 ID 排序。迁移通过权限元数据识别老板，不重建用户、不改旧密码。老板身份不能通过本版本的成员界面转移、停用、降级或授予第二个人。

在「设置与备份 → 团队账号」添加成员，每人使用独立账号。在「我的账号」修改本人密码。老板可创建管理员或员工；具备「添加员工账号」权限的管理员只能添加员工，不能创建管理员，也不能调整自己或其他人的授权。

老板打开某位成员的「角色与权限」，选择基础角色、使用中 / 停用状态，再按能力选择「继承角色」「允许」「禁止」，最后保存。继承角色使用当前角色默认值；每人例外只适用于该成员。角色和授权由服务端检查，下次请求生效；停用账号会立即注销其会话。版本冲突时重新打开成员设置核对，不覆盖他人的新授权。

| 角色 | 默认能力与固定限制 |
| --- | --- |
| 老板 | 全部能力；成员管理、商品永久清理和企业知识永久清理不可转授。知识永久清理能力名称不代表已有独立清理入口 |
| 管理员 | 默认可创建 / 导入 / 维护全库商品、恢复、合并，创建 / 编辑企业知识，添加员工，配置手动采价，使用 AI / 联网，查看全员动态，编辑 / 发布公告。模型配置、完整备份、知识停用 / 恢复、公告归档 / 恢复需老板另授 |
| 员工 | 默认可创建 / 导入、编辑 / 移除 / 恢复本人录入或负责的商品，使用 AI / 联网。老板可调整非保留能力；员工始终不能维护企业知识，即使是旧条目创建人 |

商品的「本人」范围是本人录入或当前负责人为本人；全库编辑、移除、恢复分别授权，编辑不自动包含移除或恢复。知识另有角色约束：必须是老板或管理员且有对应能力，不能将员工知识开关当作有效授权。完整备份、模型配置等非老板专属能力是否开放，以该成员实际授权为准。

复制设置或兼容管理器显示的局域网地址给可信网络内同事。软件不会修改防火墙、创建公网映射或配置开机启动。本机浏览器辅助及店铺导入还要求来自运行软件的主机；LAN 商品权限不能变成远程控制主机浏览器或清除登录资料的权限。

## 图片入库与商品资料

「批量入库」支持选择图片、选择商品文件夹、拖放图片和粘贴截图。一个文件夹可以包含同一商品的多个角度，散图先分别分组。提交前可以重命名、合并或拆分分组，并补充规格、备注、分类和平台资料。

目前的入库边界是：每批最多 300 张图片、合计 250 MB；单张最多 20 MB；一个商品最多 30 张图片。超出时请分批处理。建议保留清楚的原始主图、细节图和规格文字，不用背景相似的图片代替商品事实。

每款商品有自动生成的公司编号、名称、负责人、规格、备注和图片。原图重复提示用于发现相同文件，并不自动合并商品；同图可能出现在不同套装资料中，应由运营核对。

「AI 命名」是可选功能。生成结果先显示建议，点击采用才改名；没有配置 AI 时仍可手动命名与正常入库。

## 商品分类与运营队列

自定义分类，例如柱蜡、蜡片、水晶或模具蜡，是商品资料，和运营队列相互独立。可以按已有分类、未分类、关键词、平台、店铺和平台状态组合筛选。

运营入口的含义如下：

| 入口 | 规则 |
| --- | --- |
| 待完善 | 没有平台档案，或有未下架的 SKU 尚未填写原价格 |
| 待定价 | 没有平台档案，或有未下架的 SKU 尚未填写原价格 |
| 准备上架 | 没有平台档案，或存在人工状态为准备上架的 SKU |
| 有平台在售 | 至少一个平台 / SKU 被运营手动确认上架，即使其价格尚未补齐 |
| 全部已下架 | 已有平台记录，且所有记录都明确被手动下架 |

这些入口可以重叠。未填平台的新旧商品可以同时在三个待处理入口中找到；商品总数按款去重，不能把三个数字相加当成总数。单一商品也可同时有在售 SKU 和准备上架 SKU。

人工状态优先。软件不会因为没有价格、取得前端价或修改链接而推翻运营的上下架确认。未确认上架也不等于已下架。

## 平台与 SKC / SKU

进入商品「编辑」，在「平台与上架资料」中按产品链接 / SKC 分组。同组共用平台、店铺、SKC、前端链接和地区；每个 SKU 分别保存编号、具体规格、原价格、币种和人工状态。

- 一个商品可属于多个平台，也可在同平台多个店铺销售。
- 一个 SKC / 链接可有多个 SKU。SKU 编号的前导零会作为文字保留。
- 新 SKU 默认准备上架，不复制其他 SKU 的原价格或前端价。
- 绿色开关表示人工确认已上架，关闭表示人工下架。选择状态前请确认实际运营情况。
- 删除单 SKU 或整组先改变编辑草稿；保存前可撤销，保存后只删除目标平台资料，不删除整个公司商品或原图。

更改平台、店铺、SKC / SKU、链接、规格、地区或币种可能使旧报价不再匹配当前目标，旧报价历史仍保留。只改原价或人工上下架状态，不表示重新采集了前端价。

## 店铺筛选与人工合并

公司商品库的店铺下拉取自已有平台档案，并与平台联动。平台、店铺、上下架状态必须在同一条档案上满足条件。例如，商品在 A 店准备上架、在 B 店已上架，筛选「A 店 + 已上架」不会因 B 店状态而命中。商品整体运营队列仍按全商品的已登记 SKU 计算。

已入库商品确认同款后：

1. 在公司商品库勾选 2–50 款，点击「合并同款」。
2. 选择要保留的主商品，预览图片、平台 / 店铺分组、SKU 与数量。
3. 核对后确认。保留主商品的名称、负责人、分类、规格、备注；原图片和平台 / 店铺 / SKU、链接、人工状态、报价历史、来源信息归入主商品。不自动将相似 SKU 合为一条。
4. 源商品进入回收站，原商品资料与归属保存在持久合并记录。需要时打开「最近合并」查看并撤销；重启不会清除记录。

合并需要 `products.merge`、所有所选商品的编辑权限和源商品的移除权限；结果最多 30 张图片、100 条平台档案。预览后任何相关资料变化都需重新预览。若源商品关联企业知识，执行者还需有关知识条目的编辑权限；关联会在同一事务中迁到主商品并追加知识版本。

撤销需要合并、所有目标编辑和源商品恢复权限；受影响知识也要重新检查编辑权限。商品资料、SKU、报价、来源或知识版本 / 关联有后续变化时，直接撤销会返回冲突，不覆盖后续工作。先核对当前资料，不要用旧请求重复尝试强制撤销。撤销知识关联会追加新版本，保留全部旧版本。

合并源商品不能从普通恢复入口单独恢复；活动合并的主商品和源商品都不能永久清理。商品仍关联知识（含已停用文档）时，也要先由知识维护者明确解除关联，才能由老板按清理权限处理。技术参考见 [STORE_IMPORT.md](../STORE_IMPORT.md)。

## 从店铺前端导入试用

「批量入库 → 从店铺前端导入 · 试用」目前仅适配 **Temu，属于实验性功能**。真实专用浏览器登录实测出现回跳，尚未完成成功登录后的主图与全部变体采集验收；不承诺抓全店、抓全规格或一定成功。浏览器 / 驱动可用仅表示组件就绪，不能证明平台采集通过。能力接口明确返回 `experimental=true`、`live_capture_verified=false` 和限制原因。

1. 由具备 `products.import` 权限的成员在主机本机输入 Temu 店铺前端链接，点击「打开专用浏览器」。
2. 在专用窗口正常登录、选择地区并自行完成平台验证，再主动点击「读取店铺」。不绕过验证，不读取日常浏览器资料。
3. 选择本次发现的商品进入详情采集，每批最多 20 款。只采用页面 JSON / 可见内容中可核对的本店商品，推荐区、广告和其他店铺商品不是入库依据。
4. 在本地预览核对主图、名称、规格、各自币种 / 报价及来源链接，选择新建、并入已有商品或跳过。预览不写商品库。新建另需 `products.create`，并入另需目标商品编辑权限。
5. 明确勾选人工确认上架时，新增档案才记为上架。采集成功、存在链接或现价本身不改变人工状态。

公开商品 / 变体编号与商家 SKC / SKU 分别保存。缺少稳定变体编号时只留待补档案，不伪造 SKU 报价；缺价格、规格或店铺归属证据时显示缺项或不能入库。统一起价、划线价和插件供货价不复制成每个子产品价格。单商品超过 100 条平台档案时不能直接提交。

同平台、店铺、站点、公开商品及变体来源用于防重；重复采集不覆盖已有人工原价、当前报价、资料或上下架状态。主图会在本机安全下载、验证并建立检索特征。预览绑定当前登录会话，约 30 分钟过期，并受数量 / 内存限制；提交成功后释放图片预览内存。

若登录反复回跳，关闭采集窗口，继续使用原有图片批量入库，无需反复注册。多平台 SKU、手填当前价和现有浏览器辅助采价可独立使用。导入专用 `browser-store-profiles` 保留在本机，不复制日常 Cookie，不进入普通备份、GitHub 或公开包。真实页面、登录策略与规格完整性仍是未验证边界。详细限制见 [STORE_IMPORT.md](../STORE_IMPORT.md)。

## 本地图片查重

1. 打开「以图查重」，添加待上新品的主图或细节图，最多 5 张查询图。
2. 查看本地视觉索引状态。索引未就绪时仅有原图一致或人工确认过的记录可用。
3. 点击普通查重，先查看默认推荐的少量候选；需要时展开较弱候选。
4. 对照命中图片、规格、数量、包装与负责人，手动选择同款、待核实或不是同款。

默认最多展示 3 个推荐候选，额外候选按需展开。界面不会把未校准的检索分数称为“同款概率”。同系列不同颜色或数量也可能被召回；复杂背景、遮挡和不同角度可能漏检。

人工反馈作用于同一查询图片的后续核对，不表示模型已自动学习整个商品库。更新或重建派生视觉索引不应删除原图与业务资料。模型不可用时软件会显示受限状态。

「AI 查重」在当前用户具有 AI 使用权限且已获得视觉发送许可时，对本地召回的最多 8 款候选做图片复核。它不会搜索所有外部平台，也不会覆盖人工决定。模型结论、视觉相似与实际同 SKU 是不同层次的证据。

## 价格与浏览器辅助

### 原价、前端价与比例

卡片顶部「价格变化」打开紧凑价格表。原价格由运营手填，前端价格来自主动采集或手动录入，两者分别保留。

同币种比例为 `前端价格 ÷ 原价格 × 100%`。原价格 20、前端价 15 表示 75%（七五折），不是降价 75%。未保存的价格草稿显示待保存，暂不显示旧比例；原价为空或无可用换算时比例为 —。价格高于原价时可超过 100%。

跨币种仅按可用的 ECB 参考汇率比较，并标记「≈」、换算金额、汇率和日期。两端原币值及采价历史不改。通常 24 小时复用一次缓存；请求失败时可使用不超过 7 天的有日期缓存，5 分钟内不反复请求失败服务。没有可用率时不猜测、不按 1:1 比较，也不撤回已保存的手填价。参考率不等于银行、平台或扣费后的实际结算率。

### 主动采价

1. 在商品编辑页填写具体 SKU、原价格 / 币种、前端商品链接和目标地区。
2. 打开价格变化弹窗，点击单行「采价」或本商品「采集价格」。
3. 公开页面能够证明所选 SKU 与售价时，读取该行。多规格、区间、划线价、运费或无法确认的报价不能作为明确目标售价。
4. 失败会保留上次有效价并显示原因与时间；不要把旧记录误认为本次新价。

**本版本后台每日采价与自动上下架查询均保持停用，旧每日计划不执行。** 打开软件、保存链接或切换人工状态不自动访问平台。公共 FX 缓存按需更新不等于后台采价。

### 浏览器辅助

在主机本机地址进入对应 SKU 的「浏览器」采价区。软件打开独立的专用 Edge / Chrome 环境。请由使用者正常登录或完成网站要求的验证，选好地区、SKU 与规格，返回软件读取报价预览。

多个候选价格不会默认采用最低价。选择实际售价，核对商品 / 规格 / 地区，以及供货价、零售价、原价、优惠券等口径，再点确认记录。预览本身不写入价格；任务约 15 分钟到期，报价预览约 2 分钟到期，过期后重新读取。

不同应用用户、平台、店铺、站点和浏览器使用隔离的持久 profile。关闭采价窗口后可保留这个专用环境的平台登录，但不复制日常浏览器 Cookie。平台会话过期、风控或地区变化仍可能要求再次验证。清除此店铺登录前，先关闭关联采价任务；局域网成员不能远程控制这些窗口或清理主机 profile。

网站只返回脚本、要求验证或阻止访问时，不保证能够采价。真实 Temu 或其他平台账号登录、所有规格与所有地区并未被端到端验证，不能承诺不再登录或自动读到任意页面。

### 手填当前价格

没有链接或无法采集时，在对应 SKU 的前端价单元格填写金额和实际币种，点 ✓ 保存。该操作只更新这一行的当前价，不覆盖原价或其他 SKU。过期编辑草稿、旧网络响应和旧浏览器预览不能覆盖已经改变的 SKU 目标。发生冲突时，重新核对该 SKU 后再输入。

## 公司公告

侧栏「公司公告」显示当前有效的已发布公告及未读数量。打开公告可阅读正文、查看图片、下载获准附件，点击「标记已读」记录自己已读的公开版本。公告不是公开网页：正文和附件均要求登录与对应可见权限。已读不是理解确认、签收承诺或电子签名；重新发布产生新版本后需重新标记。

有 `announcements.edit` 权限时，点击「撰写公告」，输入标题并使用 Word 式工具排版：标题 / 段落、字号、加粗、斜体、下划线、删除线、文字 / 背景色、对齐、列表、表格、链接、撤销 / 重做和清除格式。图片可上传或粘贴，文档使用附件入口；不要求安装 Word，也不保证复制 Word 的完整版式。正文会经过安全清理，外部网页图片不能直接成为正文图片。

1. 新建后先「保存草稿」；保存仅供公告管理者核对，员工看不到新草稿或新草稿附件。
2. 可设置置顶、有效期；时间按本机输入，留空表示长期有效。标题最多 160 字，正文排版数据最多 100000 字符。
3. 有 `announcements.publish` 权限才可「保存并发布」。发布需有标题及正文或附件，并生成当前公开快照。
4. 编辑已发布公告后，只保存草稿不会改变员工看到的公开正文、置顶、期限或附件；再次发布才替换公开版本。公开版旧附件即使从工作草稿移除，在新版本发布前仍按原公开快照提供。
5. 有发布权限者可撤回为草稿，立即退出普通列表；有 `announcements.archive` 权限者可归档，恢复后回到草稿，仍需重新发布。过期公告退出普通列表，修改有效期也需发布才改变公开期限。

编辑、发布 / 撤回、归档 / 恢复分别授权。管理员默认有编辑与发布能力，归档 / 恢复须另授；其他成员是否能管理公告以其授权为准。管理者可查看版本记录；保存和状态变更检查当前版本，遇到冲突先核对其他人的修改，保留本次草稿后再处理。不要将只有归档权限当作可查看未发布工作草稿的权限。

| 公告附件 | 限制 |
| --- | --- |
| 图片 | JPG、PNG、WebP、GIF；单张最多 5 MB；会安全重编码为 JPEG、缩小至最长边 2000 像素，动画和原始格式不保留 |
| 文件 | PDF、DOCX、XLSX、PPTX、TXT、MD、CSV、JSON、ZIP；单份最多 10 MB；仅下载，不执行或解压 |
| 每篇公告 | 图片与文件合计最多 6 个、20 MB |
| 整体容量 | 最多 2000 篇公告，附件总存储上限 500 MB，历史保留的附件也计入 |

公告正文、版本、已读和附件字节保存在公司 SQLite，纳入完整数据备份。其图片及附件属于内部资料，不上传 GitHub，也不打进公开发行包。

## AI 服务与附件

### 配置和授权

老板或获 `settings.ai` 授权的成员在「设置与备份 → AI 模型服务」选择服务商，填写有效基础地址、实际可用的模型 ID 与 API 密钥，再启用并选择默认服务。密钥不应写进链接、备注、代码、截图或公开问题。

Windows 使用当前系统用户的 DPAPI 保护密钥。页面不会回显已存密钥，留空表示保留；更换基础地址会清除旧密钥，防止发往新服务。移到另一台电脑或另一个 Windows 用户后通常需要重新输入密钥。

商品文字摘要、公司知识片段和视觉图片分别需要授权。开启视觉选项前，应核实具体模型支持图片输入；同一家服务商的不同模型能力可能不同。未配置或未授权时，本地功能依然可用。连接测试也是一次实际 API 请求。

### AI 能力

- 命名：根据当前图片或真实文字生成简短内部名称，先建议再采用，不凭文件名猜商品。
- 查重：对本地候选给出依据与差异；模型建议与人工确认分别保留。
- 聊天：询问手动输入的问题，或在获准情况下参考相关商品与公司知识片段。聊天不自动修改、合并、上架、调价或删除商品。
- 思考选项：按服务商及模型显示已核实的官方选项。未知模型仅默认，不猜测其参数。更强思考可能增加等待和 Token 消耗。

这些功能复用同一服务设置与每日次数上限。次数限制不等于服务商金额预算，实际费用以账号账单为准。用户明确发送的数据会发往其选择的模型服务商；模型答案需要核实。

### 持久公司知识与对话模式

在「AI 管家 → 公司知识」新建条目，填写标题、分类和文字；也可导入 TXT、MD、CSV、JSON、PDF、DOCX、XLSX。导入沿用附件解析上限：每次最多 6 份、单份 10 MB、合计 20 MB，每份提取最多 16000 字符。只持久保存提取文字，不保存原文件和完整排版；“部分内容”不是全文。请在其他位置保留原始资料。

企业知识由当前有效公司商品和知识文档共同组成；商品、SKU、图片仍在商品库维护，不必重复导入成文档。登录成员可查阅公司共享资料，这不是支持私密文件夹的分组保密系统。新增 / 导入需老板或管理员有 `knowledge.create`；编辑需对应本人 / 全部知识权限；停用及恢复另需 `knowledge.archive`。员工即使是旧条目创建人也不能维护知识，管理员编辑权不包含停用权。查阅和本地检索不需要云端密钥。

手写知识正文最多 100000 字符，最多 2000 个条目（含停用），到限提示扩容，不会自动清理。导入只保留提取的受限文字和来源信息，不保留原文件；长文可拆分导入，原件另存。停用资料退出当前检索，仍可恢复。

在知识编辑区「关联商品」中搜索并选择最多 30 款商品。关联让 SKU / 商品问答找到相关流程与经验。商品软移入回收站后退出当前检索和星云，既有文档关联保留；正文编辑不会自动解除这些关联，但不能新挂已经移除的商品。永久清理有关联的商品前必须明确解除关联，含停用文档的关系。

知识新增、修改、停用、恢复、商品合并或撤销造成的关联变更都会留存版本与操作人；旧版不可原地覆盖。具备该知识编辑或停用权限的人可从「版本记录」只读查看旧内容、来源及当时关联，不自动回滚当前版本。旧版不进入当前 AI 检索。编辑提交当前版本号；冲突说明有人已改，先打开最新版本核对，不能直接盖过。

公司资料与版本不会按时间或使用频率衰减、遗忘或自动清理。聊天附件的约 60 分钟会话保留与企业 KB 完全分离，清空聊天不会删除公司知识。完整备份保留文档、分块、历史及关联；不要把知识库或备份发到 GitHub。

对话有三种模式：

- 「智能助手」：结合获准发送的相关公司片段，也可回答通用问题。
- 「公司知识」：优先依据本次本地检索到的内部资料回答；没有资料时说明缺口。
- 「通用对话」：不读取公司商品或知识库，仍可分析用户本次主动上传的附件。

公司商品和知识文档的发送许可各自独立。检索只提供有限的相关记录或片段，不代表全库已读完。回答中的 `[P1]`、`[K1]` 和来源卡片对应本次实际检索内容，便于回到原始记录核对。相关商品原图卡片由界面本地显示；仅展示卡片不表示模型已经视觉分析该原图。

### 知识星云

在「AI 管家 → 知识星云」浏览商品、知识、分类和 SKU。节点来自真实有效资料；连线仅代表归属分类、SKU 所属商品、人工文档关联，不是自动实体推理或完整 GraphRAG。亮度、位置、大小与动画都是视觉呈现，不代表权威、相关度概率或记忆强度。

可以输入关键词 / SKU 搜索，按商品或知识筛选，缩放 / 平移、拖动节点、暂停动态，或通过键盘可操作列表选择资料。选中后可打开商品或知识原文；选择向 AI 提问只填入聊天草稿，发送仍由用户主动完成并服从 AI 权限和资料发送许可。星图浏览、搜索和版本查看本身不调用云端模型，也不访问外部图服务。

大库图形有明确节点上限，显示全库总量、匹配及实际展示数量；未绘制的条目仍完整保存在本机并参与正常检索。停用知识和回收站商品退出当前图形，恢复后可重新出现；不会因为图上不活跃而清理资料。技术说明：[ENTERPRISE_KNOWLEDGE.md](../ENTERPRISE_KNOWLEDGE.md)。

### 显式公开联网搜索

具备模型配置权限的成员须配置并启用可用的官方 DeepSeek 搜索服务，并开启联网许可；当前用户还需 `ai.use` 和 `ai.web` 权限。聊天模型可以另选。发送前由使用者勾选「联网」，在单独的「公开搜索关键词」中填写需要公开搜索的内容，最多 128 字符。

软件只把该公开关键词送给搜索服务，不自动带上内部检索片段或完整聊天记录。请勿在这个框中填写公司机密、账号或个人资料。实际搜索结果会交给当前聊天模型，回答中的 `[W1]` 等来源可用于核对；空结果或失败会说明情况，不假装已搜索成功。

一次联网问答按一次搜索和一次模型请求计入两次额度，搜索可能单独收费，实际可用性取决于服务商账号。联网不是商品页面浏览器，也不保证能够登录店铺或取到指定 SKU 价格。

### 聊天附件

支持图片以及 TXT、MD、CSV、JSON、PDF、DOCX、XLSX。可选择、拖入或粘贴截图，发送前可预览与移除。发送失败时保留草稿和附件，便于重试。

| 限制 | 当前值 |
| --- | --- |
| 每次附件数量 | 最多 6 个 |
| 单个文件 | 最多 10 MB |
| 单次文件合计 | 最多 20 MB |
| 单份文件提取 | 最多 16000 字符，超出标明部分读取 |
| PDF | 最多 30 页；扫描件不等于可提取文字，可另传图片 |
| XLSX | 前 3 张表，每表最多 200 行、40 列 |
| 多轮引用 | 最近约 5 轮，历史与新附件合计最多 12 个、10 万字 |

文件在主机本地提取受限文字，不发送完整排版、内嵌图片或所有工作表。宏不执行，公式不计算，只显示已有缓存或未计算标记。聊天附件不会自动成为商品图片；其引用在当前登录会话的主机内存暂存约 60 分钟，重启、清空对话或容量限制也会使它失效。长期使用的资料请保留原文件，必要时重新上传。

## 动态回收站与权限

最近动态支持操作者、起止日期组合筛选，日期按北京时间整天计算；可选今天、近 7 天、近 30 天，每页 40 条，筛选针对全部历史而不是当前页。有 `audit.all` 权限时可看全员，否则仅本人的动态。

卡片支持直接编辑、单件移除和勾选本页可维护商品批量移入回收站。批量操作先检查所有目标权限，再一起执行，不故意做部分成功。回收站的原图和详情受维护权限保护；恢复保留原公司编号、图片和平台 / SKU 档案。

商品编辑、移除、恢复分别按老板授予的本人 / 全库能力判断，录入人或负责人身份本身不绕过禁止授权。不要共用一个管理员账号来代替成员账号。浏览器辅助还要求请求来自公司主机本机，其权限不因 LAN 账号拥有商品编辑权而放宽。

## 备份恢复与迁移

默认资料在程序旁 `data`，以设置显示路径为准，包括数据库、原图、缩略图、备份及可选加密 AI 配置。数据库同时保留账号 / 授权、公司知识 / 分块 / 不可变版本 / 商品关联、公告 / 图片 / 附件 / 已读和持久合并记录。专用采价及店铺导入浏览器资料（含 `browser-store-profiles`）仅在本机，不包含在现有备份导出中。

服务运行期间每天尝试一次本地自动备份，保留最近 7 份自动备份。手动生成的备份不自动清理。具备 `data.backup` 权限的成员可在设置中下载完整 ZIP，管理员默认没有该权限。请定期导出，另存到其他设备；同盘备份不能防硬盘故障。

恢复步骤：

1. 正常关闭对应共享服务，保留当前资料目录的完整副本。
2. 将备份解压到新的空目录，确认 `library.db`、`images`、`thumbnails` 位于同一层。
3. 将软件的资料目录指向该恢复目录，或将它作为程序旁的 `data`。
4. 启动后用备份时的应用账号登录，检查数量、原图、分类、SKU、价格历史、负责人、成员权限、知识原文 / 版本 / 关联、公告 / 附件 / 已读及合并记录。
5. 跨电脑或 Windows 账号迁移时重新配置 AI 密钥；店铺专用浏览器环境不随备份迁移，需重新正常登录。

不要把任何原入库图片、公告图片 / 附件、公司知识、QA 图片、店铺采样、备份、数据库、加密 API 配置或浏览器资料上传公共仓库；公开源码和发行包不携带这些资料。加密配置也属于应保护的内部文件。

## 源码运行与构建

Windows 开发基线为 Python 3.13。源码依赖与桌面运行依赖由 `requirements.txt` 固定，测试依赖见 `requirements-dev.txt`。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tools\download_model.py
.\.venv\Scripts\python.exe desktop.py
```

不需要桌面窗口的服务模式：

```powershell
.\.venv\Scripts\python.exe desktop.py --serve --host 0.0.0.0 --port 8765
```

仅本机开发可用 `--host 127.0.0.1`。`MIDOO_DATA_DIR`、`MIDOO_HOST` 和 `MIDOO_PORT` 用于资料目录和服务参数；桌面入口与 CLI 的实际设置以对应启动方式为准。

本地模型文件准备见 [`models/dinov2-small/README.md`](../models/dinov2-small/README.md)。源码仓库不提交大体积权重，`tools/download_model.py` 通过明确的准备步骤取得固定 ONNX 版本并核对 SHA256。源码用户也可下载 Releases 的 `dinov2-small-onnx-model.zip`，将核对后的模型置于说明指定位置；Setup 与完整 Windows 便携包已内置，不必另下。不要把另外一个模型随意改名后放进去。正常模型运行不向云端发送图片，也不自动下载权重。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 原管理员没有模型配置 / 备份按钮 | 这些默认保留给老板或另获授权成员，请老板核对逐人能力，不共用老板密码 |
| 知识没有编辑 / 版本按钮 | 员工始终只读；管理员也需相应知识维护权限，旧创建人不是授权 |
| 已保存公告仍显示旧内容 | 保存只更新工作草稿，需要发布权限重新发布；读者看到的是当前公开快照 |
| 合并不能撤销或源商品不能恢复 | 核对后续资料 / 报价 / 知识变更和恢复权限，从最近合并处理，不绕过冲突 |
| Temu 导入登录反复回跳 | 实验功能未完成真实登录与全变体验收，关闭采集窗口，继续图片导入，无需反复注册 |
| 桌面窗口无法启动 | 检查 WebView2，尝试兼容服务管理器；仅从官方来源安装运行环境 |
| 新安装打开空库 | 检查设置显示的资料目录，勿重新导入覆盖原库；用 `--data-dir` 指向原目录 |
| 本机可用、同事不能连接 | 检查同一局域网、主机状态、正确 IP / 端口和公司防火墙策略 |
| 提示端口被其他程序占用 | 确认占用者是否为另一实例；不要强制停止不明进程，可换 `MIDOO_PORT` |
| 查重没有结果 | 检查商品是否入库、模型与索引是否就绪，补充主图或细节图后人工复核 |
| AI 按钮不可用 | 检查默认服务、有效模型、密钥、启用状态、视觉 / 摘要授权和次数上限 |
| 网页直采失败 | 动态脚本或登录页可能没有静态报价，转本机浏览器辅助；无法确认时手填正确价格 |
| 每次都需要店铺登录 | 专用环境仅保留平台允许保留的会话，平台风控 / 过期仍需用户处理，不保证永久有效 |
| 跨币种比例为 — | 检查币种、基准价和 ECB 参考缓存是否有效，保留原金额等待网络或使用受支持币种 |
| 旧价格仍在但显示未更新 | 本次失败保留上次有效记录，请核对上次成功与最近尝试时间 |
